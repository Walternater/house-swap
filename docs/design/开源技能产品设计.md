# 房产置换助手（开源）· 产品设计

> 一句话：把「采集技能 + 分析技能 + 网页看板」打包成开源项目，让非程序员也能用同一套方法论做房产置换决策。

---

## 一、产品定位

**名称**：house-swap（房产置换助手）
**目标用户**：准备"卖旧买新"的普通人（非程序员）
**价值**：1️⃣ 采集真实房源（贝壳） 2️⃣ 双评分+资金测算+风险评估 3️⃣ 网页看板可视化 → 一键得到"该不该换/换哪套/怎么换"的决策包
**开源协议**：MIT

---

## 二、三层架构

```
house-swap/（GitHub 仓库）
├── skills/
│   ├── house-scrape/     # ①采集层：贝壳/链家数据（Kimi WebBridge 通道，opencode 已建）
│   └── house-analyze/    # ②分析层：评分/测算/风险/对比/报告/时间表（共建）
├── web/                  # ③展示层：纯静态网页看板（零依赖，双击即用）
├── docs/                 # 文档：快速开始/数据规范/政策口径/FAQ
├── config/               # user_profile.example.json（用户实测数据模板）
├── data/sample/          # 脱敏示例数据
├── LICENSE（MIT）
└── README.md
```

## 三、网页看板（核心入口）设计

### 技术选型
- **纯静态单页**（HTML+CSS+JS，无框架无后端）——双击 index.html 即用；可选 GitHub Pages 在线托管
- 评分/测算逻辑**前端实现**（与 Python 版算法一致），数据**本地处理**（隐私友好，不上传）

### 用户流程（4 步）
1. **导入数据**：上传 house-scrape 导出的 JSON/CSV，或粘贴/手动输入房源（贝壳链接可留空=待采集）
2. **填写实测财务**（一次填写，本地缓存）：月供/收入/现金/信用贷结构/归本日
3. **看板浏览**：自动算出双评分+点评+资金缺口+风险检查
4. **一键导出**：决策报告（md/html/打印）

### 看板模块（对应 analyze 技能）
| 模块 | 功能 |
|---|---|
| 📊 房源对比 | 双评分排序+筛选（预算/区域/电梯/地铁）+逐套点评+楼龄标红 |
| 💰 资金测算 | 现状月供→卖房净得→缺口情景表（300/280/260/250万）→置换后月供 |
| ⚠️ 风险雷达 | 归本炸弹/资金悖论/DTI红线/时间错配 自动检查 |
| 📅 时间表 | 90天三阶段执行计划+决策检查表 |
| 📄 报告 | 一键生成可打印决策报告 |
| 📋 政策速查 | 利率/首付/税费表（含更新日期） |

### 与采集技能的关系（重要边界）
- **采集仍是 CLI 技能**（house-scrape 需浏览器登录态，网页无法替代）
- 网页是"分析看板"，数据入口=技能导出文件或手动输入
- 后续可选：本地小服务版（python -m http.server + API 桥接采集），列为 v2 路线

## 四、开源要素

### 隐私与安全（必须）
1. 真实财务数据**不入库**：user_profile.json 加 .gitignore，只提交 example 模板
2. 示例数据**脱敏**：44套真实数据→生成假ID/假价格示例
3. 免责声明：价格/利率为估算，决策前以银行/税务/贝壳为准

### 文档清单
- README（定位+架构图+快速开始+双技能+看板截图位）
- docs/快速开始.md（普通人向：安装→采集→导入→看板→报告）
- docs/数据规范.md（schema 契约）
- docs/政策口径.md（2025-12后，标注更新日期）
- CONTRIBUTING.md（模块认领+验收标准，沿用共建规划）

### 测试
- 技能冒烟测试（3套端到端）
- 网页看板：示例数据载入→评分/测算与 Python 版结果一致（算法一致性测试）
